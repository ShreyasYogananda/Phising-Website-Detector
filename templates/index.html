      Limits you should know about

        How a link becomes a verdict

        PhishGuard only sees the address (and, if you ask, the page's visible structure). It never visits a link unless you tick the option, and it never runs a page's scripts.

        1. Read the address

          The link is split into scheme, subdomains, registered domain, path and query. A built-in public-suffix table also treats shared hosts such as github.io and pages.dev as suffixes, so one tenant is never confused with the platform.

        2. Measure {{ features|length }} things about it

          Length, character mix, randomness, brand look-alikes, risky words, odd hosts and more. Brand matching works on whole words, so "pineapple.com" is not mistaken for Apple.

        3. Run 16 transparent rules

          Each rule adds points and says why. The score is the sum, so any verdict can be traced to a named rule.

        4. Ask the learned model

          A gradient-boosting model reads the measurements, and a second model reads raw character patterns. Their calibrated probabilities are blended, and the top reasons are reported.

        5. Combine and guard

          The final score is 80% model and 20% rules. A critical rule sets a minimum score, and a verified official brand domain caps it, unless the link uses a disguise such as an IP address or an '@' prefix.
