System Architecture & Detection Pipeline End-to-End Workflow

PhishGuard utilizes an end-to-end explainable security pipeline combining RFC 3986 normalization, multi-dimensional feature extraction, and dual-model consensus verification:

Step 01
Ingest & Normalize
Strips whitespace, lowercases hostnames, validates schemes, and normalizes URL components to prevent trivial evasion.
Step 02
21 Feature Extraction
Computes lexical, structural, statistical (Shannon entropy), and brand impersonation vectors from the parsed components.
Step 03
Dual-Engine Inference
Runs both deterministic security heuristics (11 rules) and an ensemble Random Forest classifier on the exact same vector.
Step 04
Explainability Synthesis
Blends scores into a unified risk index, evaluates detector consensus and decision uncertainty, and surfaces plain-English evidence.

Key System Limitations:

  • Compromised Legitimate Sites: When an attacker compromises an authorized, reputable domain (e.g. an unpatched WordPress site) and hosts a phishing path, domain-level lexical features will appear benign.
  • Zero-Day Novel Obfuscation: Adversaries continually invent new character transformations and novel Top-Level Domains not seen in historical training data.
  • Client-Side Scripting Scope: The optional live page inspector operates in a restricted sandbox with no JavaScript execution; dynamic single-page phishing apps requiring script rendering will not reveal form fields to static HTML inspection.
